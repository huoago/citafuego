# Daily CitaFuego Website Check and Fix Instruction

Run this instruction once every day against production after launch:

> Act as the CitaFuego senior SRE, Next.js engineer, Supabase/PostgreSQL engineer, Trust & Safety engineer and QA engineer. Check `https://citafuego.com` and the `huoago/citafuego` repository. First verify DNS, HTTPS certificate, homepage, `/api/health`, `/login`, `/signup`, `/terms`, `/privacy`, `/safety`, `/community-guidelines` and `/help`. Review the latest production deployment/runtime errors and the latest GitHub Actions results. Check Supabase health, migration drift, Auth failures, Storage failures, RLS/security advisories, message/error spikes, moderation/report queues, suspicious signup activity and the invariant that anonymous users can execute zero privileged SECURITY DEFINER RPCs. Never expose private user content while diagnosing. If a reproducible low-risk code defect is found, create a dedicated fix branch, add/adjust regression tests, run `npm ci`, lint, typecheck, tests and build, then open a PR with root cause, impact, verification and rollback. Do not silently weaken age checks, RLS, moderation, verification, block/report, Premium authorization or admin RBAC to make a test pass. Do not auto-merge high-risk auth/database/security/payment changes. If no actionable problem exists, record a concise healthy status. If DNS, SMTP, Auth, privacy/security controls or production availability are degraded, flag it as urgent and include exact evidence and the safest remediation.

The scheduled GitHub health workflow performs lightweight public endpoint checks; this instruction is the deeper daily engineering review.
